# 手机端操作清单（服务端已就绪，只剩这 4 步）

服务端已经全部改好并验证：模块、脚本、选点页、链接解析都在 `wloc.bybot.si`。

## 1. 删掉旧模块

代理客户端里找到 `Apple WLOC 定位修改` → 删除。

> 必须删，不能只是关闭：新旧模块会同时拦同一个请求。

## 2. 导入新模块

| 客户端 | 订阅地址 |
|---|---|
| 小火箭 / Surge | `https://wloc.bybot.si/modules/wloc.sgmodule` |
| Quantumult X | `https://wloc.bybot.si/modules/wloc.conf` |
| Loon | `https://wloc.bybot.si/modules/wloc.lpx` |
| Stash | `https://wloc.bybot.si/modules/wloc.stoverride` |

导入后确认：模块已启用、MITM 打开、证书仍处于「完全信任」。

## 3. 快捷指令：两种做法选一种

**A（推荐，不用碰快捷指令）** 导入迁移模块，旧域名的请求自动 302 到新域名：

```
https://wloc.bybot.si/modules/wloc-migrate.sgmodule    (小火箭/Surge)
https://wloc.bybot.si/modules/wloc-migrate.conf         (Quantumult X)
https://wloc.bybot.si/modules/wloc-migrate.lpx          (Loon)
https://wloc.bybot.si/modules/wloc-migrate.stoverride   (Stash)
```

**B** 手动改：快捷指令 → 该指令 → `⋯` → 找「获取 URL 内容」，把 `wloc-spoofer.wloc.workers.dev` 换成 `wloc.bybot.si`（设置、清理两处）。若顶部显示「无法编辑」，说明作者锁了，只能走 A 或自己新建，步骤见 [`快捷指令换域名.md`](快捷指令换域名.md)。

## 4. 验证

**A. 服务通不通**（手机 Safari，代理开着）：

```
https://wloc.bybot.si/api/parse?u=https://maps.apple.com/?ll=22.5431,114.0579&format=json
```

返回 `{"lat":...,"lon":...,"name":...}` 就对了。

**B. 拦截通不通**（手机 Safari，代理开着）：

```
https://gs-loc.apple.com/wloc-settings/save?action=probe
```

返回 JSON，看 `last.evt`：

- `patched` → 一切正常，定位已改，**重启一次手机**让系统丢弃旧缓存
- `passthrough` → 先跑一次快捷指令存坐标，再看
- 打不开 / 不是 JSON → MITM 或证书问题，回第 2 步
- `parse-fail` → Apple 换了响应格式，看 `docs/troubleshooting-ios26.md` 第 4 节

## 日常

| 情况 | 做法 |
|---|---|
| 切了坐标不生效 | 重启手机（iOS 26 只有重启能清 locationd 缓存） |
| 想换位置 | 地图选点 → 分享 → wloc 快捷指令 → 重启或等系统重新取点 |
| 恢复真实定位 | 跑「wloc 清理恢复位置」→ 重启 |
| 模块参数 | 保持默认（113.94114 / 22.544577），填了会覆盖快捷指令存的坐标 |
